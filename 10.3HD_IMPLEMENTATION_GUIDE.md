# SIT722 Task 10.3HD Implementation Guide

## Selected feature

**Cost-Aware Infrastructure as Code and Automated AKS Cost Control**

This implementation extends the Week 08 KoalaTech CI/CD project. It keeps the existing application delivery pipeline and adds two complementary controls:

1. A Terraform cost gate that estimates the planned AKS worker-node cost from the Terraform plan using the official Azure Retail Prices API.
2. A running-cost control loop that checks Azure month-to-date cost and can stop AKS when a configured threshold is reached. A simulation mode is included so the control logic can still be demonstrated if the student subscription does not expose the Cost Management API to the service principal.

The project also contains scheduled/manual AKS sleep and wake actions and Discord notifications.

# 5. Cost Management API permission

The Azure Retail Prices API used by the Terraform gate is public and does not require Azure authentication.

The month-to-date budget workflow is different. It calls the authenticated Azure Cost Management Query API. The existing Contributor role may already allow the service principal to read subscription cost data. If the query returns an authorization error, assign **Cost Management Reader** to the service principal at subscription scope.

First obtain the service-principal client ID from your `AZURE_CREDENTIALS` JSON, then run:

```bash
SUBSCRIPTION_ID=$(az account show --query id -o tsv)
SP_OBJECT_ID=$(az ad sp show --id <CLIENT_ID> --query id -o tsv)

az role assignment create \
  --assignee-object-id "$SP_OBJECT_ID" \
  --assignee-principal-type ServicePrincipal \
  --role "Cost Management Reader" \
  --scope "/subscriptions/$SUBSCRIPTION_ID"
```

If the student subscription does not permit this role/API, do not spend time fighting the subscription type. Use the workflow's **simulation** mode for the threshold demonstration and explain that the same evaluator and AKS action are used, with only the cost source replaced.

# 19. Suggested report wording

## Introduction

This project extends the Week 08 KoalaTech Continuous Delivery pipeline with cost-aware infrastructure automation. The existing pipeline already tests the application, builds and publishes container images, deploys to AKS staging, validates the deployment and promotes the tested image set to production. My improvement adds cost as an automated DevOps decision rather than checking cloud spending only after resources have been deployed.

## Feature 1: Cost-aware Infrastructure as Code

Terraform is executed through GitHub Actions with remote Azure state. Pull requests run formatting, validation and a Terraform plan before any infrastructure change is accepted. A custom Python cost gate reads the planned AKS node count and VM size, obtains the current VM rate from Microsoft's Azure Retail Prices API and calculates the planned hourly and approximate monthly worker-node cost. If the hourly value is above the configured limit, the pull request fails. An intentional increase can be approved with a `cost-approved` label, which is also recorded through Discord.

## Feature 2: Automated AKS cost control

A second workflow controls the running AKS environment. It supports scheduled and manual sleep/wake operations using Azure CLI. Another workflow queries month-to-date subscription cost through the Azure Cost Management API and compares it with a configurable percentage of the monthly budget. When the threshold is reached, the workflow can automatically stop AKS and report the action to Discord. A simulation mode uses the same decision and enforcement path when the student subscription does not provide the required Cost Management API access.

## Testing and outcome

The feature is tested at several levels. Python unit tests verify plan parsing, Azure retail-price filtering and threshold calculations. Pipeline tests demonstrate a normal three-node configuration passing the cost gate, a deliberately more expensive configuration being blocked and an approved override succeeding. The running control loop is tested with values below and above the budget threshold, followed by an actual AKS stop/start verification. Finally, the original backend/frontend CI, container publication and staging delivery pipeline are run again to confirm that the cost controls extend rather than replace the existing deployment process.

## Reflection

The main change in my understanding was treating cost as a system state that can be tested and acted on automatically. Previously Terraform created the infrastructure and monitoring showed what the environment was doing. In this implementation the pipeline makes a decision before a costly change is accepted, while the running environment can also react later when spending reaches a defined limit. The combination of a pre-deployment cost gate and a post-deployment control loop makes cloud cost part of the same automated feedback process as testing and deployment.
